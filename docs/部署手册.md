# MyPanel 部署手册（京东云雅典娜 RE-CS-02 / ARM64 路由器）

> 本手册针对本仓库（基于 docker-butler 源码改造的私有版 MyPanel）编写，
> 目标设备：京东云雅典娜 RE-CS-02（ARM64，2.83GB 内存，4 线程，Docker 29.x）。
> 其它 ARM64 路由器同样适用，只需按实际路径调整。

---

## 一、设备与 Docker 信息（RE-CS-02 实测）

| 项目 | 值 |
| --- | --- |
| CPU 架构 | aarch64 / arm64 |
| 内存 | 2.83 GB |
| 线程数 | 4 |
| Docker 版本 | 29.6.1 |
| API 版本 | 1.55 |
| Docker 根目录 | `/mnt/mmcblk0p27/docker`（85.85 GB 可用） |
| 索引服务器 | `https://index.docker.io/v1/` |
| 镜像加速器 | 可在面板内配置 |

> 确认 Docker 根目录：`docker info 2>/dev/null | grep "Docker Root Dir"`
> 确认架构：`uname -m`（应输出 `aarch64`）

## 二、端口与挂载设计

- **端口映射**：宿主机 `8383` → 容器内 `8383`（可改 `ports` 左边数字）
- **privileged: true**：管理 Docker 必需，不能去掉
- **pid: host**：让“端口占用扫描”能读到宿主真实监听端口
- **数据目录**：`./mypanel-data`（项目目录下，方便备份）
- **Compose 目录挂载**：`/mnt/mmcblk0p27/docker → /host/compose`，`/mnt/mmcblk0p27 → /host-vol1`

## 三、准备工作

1. ✅ 路由器已装 Docker 与 Docker Compose v2（`docker compose version` 有输出）
2. ✅ 能 SSH 登录路由器
3. ✅ 已知你的 Docker 目录（默认 `/mnt/mmcblk0p27/docker`）

## 四、部署启动

### 方式 A：GitHub Actions 多架构镜像（推荐）

仓库已含 `.github/workflows/build.yml`，推送 `main` 后自动构建 `linux/amd64,linux/arm64` 并推送 GHCR。

```bash
# 1. 进入你的 Docker 项目目录
cd /mnt/mmcblk0p27/docker

# 2. 克隆仓库
git clone https://github.com/fanling1970/mypanel.git
cd mypanel

# 3.（可选）私有包需先登录，公开包可跳过
# docker login ghcr.io

# 4. 启动
docker compose up -d

# 5. 查看状态
docker ps | grep mypanel
```

### 方式 B：路由器本机源码构建

```bash
cd /mnt/mmcblk0p27/docker
git clone https://github.com/fanling1970/mypanel.git
cd mypanel
docker compose -f docker-compose.build.yml up -d --build
```

构建会自动按 arm64 下载 docker CLI 与 compose 二进制，无需外网镜像。

### 方式 C：docker run 一条命令

```bash
docker run -d \
  --name mypanel \
  --restart unless-stopped \
  --privileged \
  --pid host \
  -p 8383:8383 \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v $(pwd)/mypanel-data:/data \
  -v /etc/docker/daemon.json:/etc/docker/daemon.json \
  -v /mnt/mmcblk0p27/docker:/host/compose \
  -v /mnt/mmcblk0p27:/host-vol1 \
  -e TZ=Asia/Shanghai \
  -e DB_PATH=/data/mypanel.db \
  -e APP_PORT=8383 \
  ghcr.io/fanling1970/mypanel:latest
```

## 六、核心功能一览

### 6.1 定时调度（最核心）
给容器设置定时任务：定时启动/停止/重启/更新。支持自然语言（「每天早上8点启动 nginx」）或 Cron 表达式。
路径：容器列表 → 「定时」按钮 → 新建任务。

### 6.2 一键更新
- 容器列表 → 「更新」→ 实时进度条
- 支持「自动检查」开关
- **面板自更新**：Compose 列表里本服务行 → 「检查更新」→ 「更新自己」

### 6.3 Compose 项目管理
- 自动识别宿主机所有 Compose 项目，项目级启停/重启/更新
- 新建项目可粘贴 compose 内容、浏览目录、端口占用扫描

### 6.4 镜像管理
镜像列表、一键清理未使用/悬空镜像、镜像加速器设置、本地 tar 导入。

### 6.5 端口占用扫描
新建 Compose 项目时点「端口占用」，列出宿主机全部占用端口，避免冲突。

## 七、常用命令速查

| 场景 | 命令 |
| --- | --- |
| 启动 | `docker compose up -d` |
| 停止 | `docker compose stop` |
| 重启 | `docker compose restart` |
| 看日志 | `docker compose logs -f` |
| 删除（保留数据） | `docker compose down` |
| 彻底删除（含数据） | `docker compose down -v` |

## 八、更新版本

### 面板自更新（推荐）
1. Compose 列表 → 本服务行 → 点「检查更新」
2. 显示“有更新” → 点「更新自己」
3. 确认 → 面板离线约 30 秒 → 自动恢复
4. 重新登录 → Ctrl+F5 强刷

### 手动更新
```bash
cd /mnt/mmcblk0p27/docker/mypanel
docker compose pull
docker compose up -d
```

## 九、常见问题 FAQ

| 现象 | 解决办法 |
| --- | --- |
| `no matching manifest for linux/arm64` | 上游镜像无 arm64。请用本仓库镜像 `ghcr.io/fanling1970/mypanel`（CI 已构建 arm64），或方式 B 本机构建 |
| 检查更新一直“已是最新” | 用本仓库改造后的源码；必要时设 `ARCH_OVERRIDE=arm64` |
| 拉镜像失败 | 「镜像管理 → 加速器」配置国内加速器，保存后重启 Docker |
| 面板打不开 | `docker ps` 看状态，`docker compose logs -f` 看日志；端口 8383 是否被占用 |
| 提示 privileged 警告 | 管理其他容器需要特权模式，不能去掉 |
| 端口占用扫描无“系统监听” | 检查 compose 里 `pid: host` 是否还在 |
| 浏览器打开是旧页面 | Ctrl+F5 强刷（升级后前端有缓存） |
| 忘记 admin 密码 | `docker compose down && rm -rf ./mypanel-data && docker compose up -d`（清空配置，慎用） |

## 附录：compose 配置说明

| 配置项 | 说明 |
| --- | --- |
| `ports: "8383:8383"` | 宿主机端口:容器内端口，左边可随意改 |
| `APP_PORT=8383` | 容器内监听端口，与 ports 右边保持一致 |
| `privileged: true` | 管理 Docker 必需，不能去掉 |
| `pid: host` | 端口占用扫描读宿主监听必需 |
| `./mypanel-data:/data` | 数据目录（定时任务、设置、日志） |
| `COMPOSE_ROOT` | 宿主机 Docker 项目目录（默认 `/mnt/mmcblk0p27/docker`） |
| `COMPOSE_VOLUME_ROOT` | 宿主机存储根（默认 `/mnt/mmcblk0p27`） |
| `ARCH_OVERRIDE` | 可选，强制指定架构（如 `arm64`），一般无需设置 |
